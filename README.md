# Baburism

Сайт пространства художника Бабура Исмаилова: произведения, будущая коллекция предметов, интервью и посещение пространства. Три языка (RU / UZ / EN), каталог с избранным и подготовкой обращения в Telegram, интерактивное рассматривание живописи.

Это статический сайт: каждая страница собирается в HTML на этапе сборки и публикуется на **GitHub Pages**. Сервера, базы данных и ключей нет.

## Возможности

- **Hero** из шести картин: смена каждые 9 секунд, пауза вне экрана, при открытом меню и при `prefers-reduced-motion`; следующее изображение декодируется до показа.
- **«От целого к детали»**: масштаб до 300%, перемещение, мини-карта, большой просмотр, жесты на тач-экранах и клавиатура.
- **Каталог**: поиск по всем переводам, категории, наличие, ползунок цены, сортировка; состояние живёт в адресе страницы и восстанавливается при возврате из карточки.
- **Избранное без регистрации**: хранится в браузере, делится ссылкой. Из него готовится текст обращения со ссылками на карточки; Telegram открывается с готовым черновиком, а отправляет его сам посетитель.
- **Лента «Выбор Baburism»**: бесконечная, управляется мышью, колесом, клавиатурой и касанием; на телефоне прокруткой владеет браузер.
- **Журнал**, страницы произведений, пространства и посещения, политика конфиденциальности.
- Доступность: фокус и `inert` под модальными окнами, нативные `<dialog>` и popover, уважение `prefers-reduced-motion`, понятные подписи.

## Стек

| Область    | Решение                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------ |
| Фреймворк  | [React Router 7](https://reactrouter.com) (framework mode, `ssr: false` + `prerender`), React 19 |

| Качество   | ESLint 10 (typescript-eslint, react-hooks), Prettier                                             |
| Публикация | GitHub Actions → GitHub Pages                                                                    |

## Быстрый старт

Нужен Node.js 22.18 или новее.

```bash
npm ci
npm run dev
```

Сайт откроется на `http://localhost:5173`. Проверка перед коммитом: `npm run check` (формат, линт, типы, тесты).

### Сборка как на GitHub Pages

Проектный сайт живёт по адресу `https://<пользователь>.github.io/<репозиторий>/`, поэтому сборке нужны путь и адрес:

```bash
BASE_PATH=/baburism-site SITE_ORIGIN=https://<пользователь>.github.io npm run build
BASE_PATH=/baburism-site SITE_ORIGIN=https://<пользователь>.github.io npm run verify
BASE_PATH=/baburism-site npm run preview
```

`preview` отдаёт `build/client` так же, как GitHub Pages: сайт под своим путём, редирект на адрес со слэшем, `404.html` со статусом 404. В Git Bash на Windows путь с ведущим слэшем превращается в путь к Git: пишите `BASE_PATH=baburism-site` или запускайте через PowerShell.

Без `BASE_PATH` сайт собирается для корня домена (подходит для собственного домена и репозитория `<пользователь>.github.io`).

## Публикация

1. В репозитории: **Settings → Pages → Source: GitHub Actions**.
2. Любой push в `main` запускает `.github/workflows/deploy.yml`: проверки → сборка → проверка сборки → публикация.
3. Путь и адрес сайта workflow получает сам от `actions/configure-pages`, ничего прописывать не нужно.

## Как менять содержимое

| Что менять                                      | Где                                                                        |
| ----------------------------------------------- | -------------------------------------------------------------------------- |
| Предметы, статьи, категории, контакты, Telegram | `content/` (подробности в [content/README.md](content/README.md))          |
| Тексты интерфейса (все три языка рядом)         | `messages.ts` в папке нужной функции, `app/shared/i18n/common-messages.ts` |
| Картины, их размеры и подписи                   | `app/shared/content/artworks.ts`, файлы в `public/art/`                    |
| Оформление                                      | `app/styles/`                                                              |

Типы требуют все три перевода для каждого текста интерфейса: забытый перевод не пройдёт `npm run typecheck`.

## Архитектура

```
app/
  routes.ts              карта адресов
  root.tsx               HTML-документ, шрифт, стили, границы ошибок
  routes/                тонкие модули: meta + страница из features/
  features/              вертикальные срезы
    layout/              шапка, меню, подвал, лайтбокс, оболочка, смена языка
    home/ about/ artworks/ journal/ privacy/ visit/
    catalogue/           фильтры (чистая логика) и интерфейс каталога
    shop/                избранное, карточка предмета, обращение в Telegram
    explorer/            геометрия и интерфейс рассматривания картины
    ribbon/              движение бесконечной ленты (десктоп и тач)
  shared/
    content/             схемы, разбор контента, картины, Telegram, видео
    i18n/                языки, контекст, общие тексты
    routing/             адреса с учётом базового пути, мета-теги
    hooks/ ui/ dom.ts    общие хуки, иконки, DOM-утилиты
content/                 данные сайта
scripts/                 завершение сборки, предпросмотр, проверка сборки
tests/                   модульные тесты чистой логики
```

Принципы:

- **Чистая логика отделена от интерфейса.** Фильтры, избранное, обращение, геометрия просмотра и разбор контента не зависят от React и покрыты тестами.
- **Ничего не рендерится «потом».** Все страницы готовы как HTML до загрузки скриптов; состояние из адреса или `localStorage` подключается после гидратации, поэтому первый кадр совпадает со статическим HTML.
- **Движение — улучшение, а не условие.** Содержимое видно без JavaScript и до срабатывания анимаций; при `prefers-reduced-motion` анимации не запускаются.
- **Контент проверяется при сборке**, а не на странице посетителя.

## Что делает сайт без сервера

- Форма «Написать» и «Обсудить в Telegram» готовят сообщение и открывают чат Telegram; отправляет его посетитель. Пока в `content/settings.json` не указан `salesTelegram`, кнопки отключены и честно объясняют почему.
- Избранное хранится только в браузере посетителя.
- Заявки не сохраняются нигде, поэтому уведомлений и панели редактора нет: контент правится в репозитории.
